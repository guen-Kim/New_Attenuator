# New_Attenuator 모드 정리

이 문서는 현재 프로그램에 포함된 11개 모드를 정리한 내용이다.

- `Basic1`, `Basic2`는 현재 코드에서 실제 동작이 구현되어 있다.
- `Basic3`, `Transform2`는 현재 자동 동작이 비어 있어 확장용 자리로 볼 수 있다.
- `Step Handover`, `Ping-Pong Handover`, `Diagonal Handover`, `Failover Recovery`는 추가 후보 시나리오로 정의한 항목이다.

| 모드 | 설명 | 목적 | 장점 | 예 |
|---|---|---|---|---|
| `Basic1` | 2개의 AP를 서로 반대 방향으로 감쇠시키는 교차 제어 모드이다. 한쪽은 감쇠를 올리고 다른 한쪽은 내렸다가 다시 반대로 복귀한다. | 두 AP 간 전환이 부드럽게 되는지, 감쇠 변화에 따른 링크 반응을 확인한다. | 단순하고 직관적이라 디버깅이 쉽고, 교차 전환 성능을 빠르게 확인할 수 있다. | `AP1: 0→40`, `AP2: 40→0` 후 반대로 복귀 |
| `Basic2` | 선택된 AP들을 하나씩 순서대로 감쇠 스윕하는 모드이다. 각 채널을 `Low`에서 `High`까지 올린 뒤 다음 채널로 넘어간다. | 개별 AP의 감쇠 반응, 순차 스윕 동작, 채널별 특성을 확인한다. | 특정 채널만 분리해서 볼 수 있어 문제 채널 찾기에 좋고, 반복 테스트에 적합하다. | `AP1`만 0→40 스윕 후 복귀, 다음에 `AP2`, 그다음 `AP3` 순서로 진행 |
| `Basic3` | 현재 자동 동작이 구현되어 있지 않은 기본 시나리오 자리이다. | 추후 추가 예정인 기본 테스트 시나리오용 자리이다. | 향후 단순 반복, 정지, 랜덤 스윕 같은 기본 검증 로직을 넣기 쉽다. | 현재 없음 |
| `Transform1` | 2개씩 묶은 AP 그룹을 순차적으로 약화시키는 전환 테스트이다. 실제 코드에서는 `AP1/AP3`를 먼저 감쇠시키고, 이어서 `AP2/AP4`를 감쇠시킨다. | 그룹 단위 전환에서 로밍과 handover가 어떻게 보이는지 확인한다. | 4개 AP를 한 번에 보지 않고 그룹으로 나눠서 점진적 전환을 검증할 수 있다. | `AP1, AP3`만 0→40, 잠시 대기 후 `AP2, AP4`만 0→40 |
| `Transform2` | 2개 AP 쌍을 동시에 전환하는 모드이다. 예를 들어 `AP1/AP2`와 `AP3/AP4`를 각각 한 쌍으로 묶어 같은 타이밍에 감쇠를 교차 적용한다. | 다중 링크가 동시에 바뀌는 환경에서 전환 안정성과 간섭 영향을 확인한다. | 한 번에 2개 링크 흐름을 검증할 수 있어 실제 운용 환경에 더 가깝고, 병렬 전환 문제를 찾기 좋다. | `AP1↓ + AP2↑`, `AP3↓ + AP4↑`를 동시에 반복 |
| `Transform3` | 4개 AP를 하나씩 순서대로 감쇠시키는 순차 로밍 모드이다. 한 AP가 약해지면 다음 AP로 넘어가는 식으로 반복한다. | AP 간 단일 이동 경로에서 로밍 순서와 안정성을 확인한다. | 가장 로밍 테스트답게 단순한 전환 흐름을 만들 수 있어 패턴 확인이 쉽다. | `AP1 → AP2 → AP3 → AP4 → AP1` 순서로 하나씩 감쇠 |
| `Transform4` | 한 AP는 약해지고 다음 AP는 강해지는 형태로 겹치며 넘어가는 순차 handover 모드이다. 예: `AP1 fade out / AP2 fade in` 형태로 이어진다. | 실제 로밍처럼 이전 AP가 줄어드는 동시에 다음 AP가 올라오는 전환을 검증한다. | 가장 실전적인 전환 패턴에 가깝고, 끊김 없는 handover 동작 확인에 유리하다. | `AP1↓ + AP2↑`, 다음에 `AP2↓ + AP3↑`, 다음에 `AP3↓ + AP4↑` |
| `Step Handover` | AP를 한 칸씩 순차적으로 넘기는 단순 handover 모드이다. `AP1 -> AP2 -> AP3 -> AP4` 순서로 이동한다. | 가장 기본적인 로밍 순서를 검증한다. | 흐름이 단순해서 디버깅이 쉽고, 전환 지점별 반응을 명확히 확인할 수 있다. | `AP1`을 약화한 뒤 `AP2`를 강화, 이후 `AP2 -> AP3 -> AP4`로 순차 이동 |
| `Ping-Pong Handover` | 두 AP 사이를 반복해서 오가는 모드이다. 예: `AP1 <-> AP2`를 계속 전환한다. | 특정 AP 쌍에서의 반복 전환 안정성, 끊김, 지연 여부를 확인한다. | 재현성이 좋아 문제를 반복해서 확인하기 쉽고, 로밍 흔들림을 테스트하기 좋다. | `AP1↓ / AP2↑` 후 `AP2↓ / AP1↑`를 반복 |
| `Diagonal Handover` | 인접하지 않은 AP로 건너뛰는 전환 모드이다. 예: `AP1 -> AP3 -> AP2 -> AP4`처럼 대각선 경로로 이동한다. | 비연속적인 AP 선택 상황에서 경로 전환 로직을 검증한다. | 일반적인 순차 이동과 다른 경로를 테스트할 수 있어 선택 알고리즘의 약점을 찾기 좋다. | `AP1`에서 시작해 `AP3`으로 전환, 다음에 `AP2`, 그다음 `AP4` |
| `Failover Recovery` | 정상 AP를 급격히 약화시키고 다른 AP를 즉시 복구시키는 장애 대응형 모드이다. | 장애 발생 시 자동 복구와 우회 동작을 검증한다. | 실제 장애 상황을 모사할 수 있어 복원력 평가에 유리하다. | `AP1`을 빠르게 `end`로 보내고 `AP2`를 즉시 `start`로 복귀 |

## 요약

- `Basic` 계열은 단순 감쇠 스윕과 채널별 반응 확인에 적합하다.
- `Transform` 계열은 AP 간 전환, 로밍, handover 검증에 적합하다.
- `Basic3`와 `Transform2`는 현재 확장용 자리이며, 이후 필요한 시나리오를 추가할 수 있다.
